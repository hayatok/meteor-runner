## 1) 仕様との不一致

**v2（`docs/UPDATE_V2.md`）**

- **B.5：衝突後のスローがシーン全体に適用されていない。** `src/main.js` の `crashing` 分岐では、ワールドの移動と粒子には `elapsed * 0.25` を渡す一方、`presentation.present(run, elapsed)` には実時間を渡しています。`src/world.js` の `present()` はその値で `time` を進めるため、空のシェーダーや高速時のカメラ微振動は通常速度のままです。シェイクの指定時間を実時間で保つこととは別に、シーン内でスローのかかる動きとかからない動きが混在しています。

**基本設計（`docs/GAME_DESIGN.md`）**

- **§6：衝突演出中は手動・自動ポーズが効かない。** `src/main.js` の `togglePause()` と `visibilitychange` は、停止対象を `playing` と `countdown` に限定しています。`src/ui.js` の `show()` は `impact` と `crashing` でも HUD の一時停止ボタンを表示するため、衝突後は画面ボタンも Esc も反応せず、タブを非表示にしてもポーズ状態には入りません。
- **§4：結果画面から即再走できない。** `src/main.js` では `start` と `restart` が同じ `startRun()` を呼び、毎回 `countdown` に入ります。`GO!` まで約3秒間、走行も操作入力も始まりません。カウントダウン自体は v3 の追加演出ですが、リスタートにも適用する現実装は基本設計の「即再走」と一致しません。

## 2) バグ・不公平な生成・境界条件の問題

- **走行中にミュートをクリックすると、Space でジャンプできなくなる。** `src/main.js` の `toggleMute()` はクリック後にボタンのフォーカスを外しません。`src/input.js` は `HTMLButtonElement` にフォーカスがあると Space の処理を早期終了するため、キーボードフォーカスがミュートボタンに残る環境では、次の Space がジャンプではなくミュート切替になります。

## 3) パフォーマンスとメモリの問題

- **描画対象がなくても頂点バッファを毎フレーム再転送する。** `src/effects.js` は星屑の残光がなく `visibleTraces === 0` のフレームでも `tracePoints.needsUpdate = true` にします。`src/particles.js` も、ダストを止めて破片が消えた結果画面で、位置・色・サイズの3属性を毎フレーム更新扱いにします。変更範囲を指定していないため、表示する粒子がなくても属性バッファ全体が転送対象になります。
- **HUD の表示値が変わらないフレームでも整形と割り当てが発生する。** `src/main.js` は走行中の各描画フレームで `ui.update(run)` を呼びます。`src/ui.js` は DOM 書き換えを `setText()` で抑えていますが、その比較前にスコアと距離を `toLocaleString('ja-JP')` で整形し、パワー表示用の配列も新規作成しています。

## 4) 良い点

- `src/main.js` は走行判定を 120 Hz の固定ステップに分離しており、描画フレーム間隔がそのまま衝突判定の刻みにならない構成です。
- `src/particles.js` は演出用の乱数を独立させており、適応品質で粒子数が変わっても、走行中の障害物生成が使う乱数列を消費しません。
