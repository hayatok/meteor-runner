## 1) 仕様との不一致

- **空のフェーズが、設計書 §1 の4区間に対応していない** — `src/world.js` の `pose()` は `(distance % 3000) / 500` で、500mごとに6組の色を順番に使います。§4・§7の「500mごとの色変化」はありますが、§1で一つのフェーズとされる「夜」500–1500mと「深夜」1500–2500mを、それぞれ別々の2区間に分けており、色の切り替えと4フェーズの区分が実装上分かれていません。
- **提出バンドルに必須のGLBとビルド用マニフェストがない** — `src/models.js` は `models/${name}.glb` を11種類読み込みますが、提示されたバンドルには `public/models/*.glb` がなく、この内容のまま配信すると全モデルがフォールバックになります。また、`package.json` がないため、このバンドル単体では §6 の `npm run build` を実行できません。Blender製アセットの内容と、ビルド成果物のサブパス配信は確認できません。

## 2) バグ・不公平な生成・境界条件の問題

- **障害物の端では、機体が見た目上重なっても衝突しない** — `src/runner.js` の `passObstacle()` は、バリアを含む障害物の横判定を原点間の距離 `gap < 1.08`（`asteroid_b` のみ `1.16`）で決め、機体の幅や傾きを考慮しません。たとえば `src/models.js` のフォールバックでは、バリアの梁は中心から左右1m、機体上部の荷物は中心から左右0.24mあります。通常ホバー時は荷物が梁の下端より高いため、横差が約1.1mのレーン移動中には、ダイブなしで梁と荷物が重なっても横判定で除外されます。
- **マグネット終了時に、吸着途中の星屑の位置が不連続になる** — `src/runner.js` の `advance()` は毎ステップ `position.z` を元の走行位置に戻し、`collect()` はマグネット有効中だけそこに `1 - item.pull` を掛けます。一方、吸着で動いた `position.x` と `position.y` は復元しません。未取得のまま効果が切れると、星屑は奥行きだけ元の軌道へ跳び、横と高さは引き寄せられた位置に残ります。
- **遠方でデッキが途切れ、その先に障害物や星屑が表示され得る** — `src/world.js` のデッキは30mの5枚で、フォールバック形状の奥端は `z = -120 + distance % 30` です。継ぎ替え直前には約 `-90m` までしか床がありませんが、`src/runner.js` は約100m先まで行を生成し、星屑は行のさらに最大4m先に置きます。床より先にオブジェクトが見え、30mごとの継ぎ替えで床の奥端が約30m伸びます。

## 3) パフォーマンスとメモリの問題

- **静止中も毎フレーム3Dシーンを描画する** — `src/main.js` の `setAnimationLoop()` は、状態にかかわらず `world.render()` を呼びます。タイトル・ポーズ・結果画面では `run.advance()` が止まり、シーンの姿勢も更新されないため、同じシーンの描画が続きます。
- **固定ステップのたびに描画用の姿勢まで更新する** — `src/main.js` は1描画フレーム内に `run.advance(step)` を複数回実行し、`src/runner.js` はそのたびに `world.pose(this)` を呼びます。`src/world.js` の `pose()` はデッキ5枚、背景の岩24個、カメラ、空とライトを更新しますが、描画に使われるのは最後のステップの状態だけです。
- **GLBへの差し替え時に、不要になったフォールバックの描画リソースを明示解放しない** — `src/models.js` のロード成功処理は `model.template` を置き換え、`clear()` で旧メッシュを外します。クローン間で共有されていた旧ジオメトリや、フォールバック惑星専用のリング材質には `dispose()` が呼ばれないため、すでに描画されたリソースのGPU側の解放が保証されません。

## 4) 良い点

- `src/runner.js` は1行の障害物を最大2レーンに制限し、星屑の列を空きレーンに置いています。障害物と星屑のインスタンスは種類別プールで再利用しています。
- `vite.config.js` と `src/models.js` の相対パス設定は整合しています。モデルのロード失敗時もフォールバックが残り、WebGLレンダラーの初期化に失敗した場合は `src/main.js` が専用エラー画面を表示します。
