## 1) 仕様との不一致

**v2 受け入れ基準**

- **［ブロッカー］提示バンドルではビルドできない。** `src/main.js` が `import './style.css'` を実行しますが、バンドルに `src/style.css` がありません。`package.json` の `npm run build` は `vite build` を呼ぶため、この相対インポートを解決できません。ビルド実行やサブパス配信での GLB の HTTP 200 は未確認です。
- **［A.2］フォールバック時に、空の背景に指定外の紫系色が出る。** `src/world.js` は `planet` を背景に配置しています。`src/models.js` の惑星フォールバックは本体に `#4a4062`、リングに `#a78ba5` を使います。フェーズ補間そのものではなく、モデル読み込み失敗時に表示される背景の問題です。
- **［C］星屑取得音の音程がコンボ24で頭打ちになる。** `src/audio.js` の星屑音は `74 + Math.min(combo, 24)` です。`src/runner.js` のコンボは24を超えて増え、HUDの倍率も ×3.4 から ×8.0 まで上がりますが、その間の取得音は同じ音程です。

**基本設計**

- **［§6］致死衝突の演出中は一時停止できない。** `src/main.js` の `togglePause()` は `playing` と `paused` だけを扱い、`visibilitychange` も `playing` のときしか停止しません。一方、`src/ui.js` の `show()` は `crashing` 中も一時停止ボタンを含む HUD を表示します。この間は画面ボタンも Esc も効かず、タブを隠しても自動ポーズになりません。

## 2) バグ・不公平な生成・境界条件の問題

- **衝突直後にタブを切り替えると、復帰時にスロー演出を飛ばして結果画面へ進む。** `src/main.js` の `crashing` 分岐は、前フレームからの経過時間を `Math.min(crashRemaining, frameTime)` で消化します。非表示中に描画が止まり、残り時間以上経ってから復帰すると、復帰の最初のフレームで残り時間を使い切り、そのまま `ui.finish(run)` を呼びます。
- **スマホ操作は、ブラウザーにジェスチャーを取られた場合に途切れる。** `src/input.js` はポインターをキャプチャしますが、キャプチャ自体はブラウザーのパンを抑止しません。ブラウザーが24 pxのスワイプ判定より先にジェスチャーを引き取ると、キャプチャが失われ、`lostpointercapture` で操作が破棄されます。キャンバスの `touch-action` を指定するコードは提示バンドルにないため、実機での操作成立は確認できません。

## 3) パフォーマンスとメモリの問題

- **粒子プールは生成時の負荷を抑えているが、描画は粒子ごと。** `src/effects.js` は100個の粒子それぞれに `Mesh` と透明な `MeshBasicMaterial` を持たせています。ジオメトリは共有していますが描画はまとめておらず、画面内の粒子が重なると最大100個分の描画呼び出しが加わります。
- **HUDの値が変わらないフレームでも表示文字列を作り直す。** `src/main.js` はプレイ中の描画フレームごとに `ui.update(run)` を呼び、`src/ui.js` は変更比較の前にスコア・距離を `toLocaleString('ja-JP')` で整形し、倍率・速度の文字列と効果表示用配列も作ります。`setText()` が省くのはDOMへの書き込みだけです。

## 4) 良い点

- `src/runner.js` は描画側とイベント通知を外から受け取るため、衝突・得点・ミッションのロジックを WebGL や WebAudio なしで検証しやすい構造です。
- `src/models.js` は GLB の読み込み完了時にモデルの中身だけを交換するため、走行中に差し替わっても配置やプールが参照するオブジェクトは維持されます。
